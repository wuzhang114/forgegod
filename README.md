# 锻造之神 · ForgeGod

一个西幻题材的独立游戏原型。玩家开一间铁匠铺,从材料、工艺、热处理的取舍里打出一把武器;然后带着这把武器去见锻造之神——不是从技能列表里挑,而是用自然语言向神申请一个"此前不存在"的机制;神会根据武器的档案(材料、缺陷、工艺事实)质询、还价或驳回;谈成后,契约编译成可执行的机制代码,小队带着它上六边形棋盘的战场;打完回来,赏金、伤势、库存、天数都留在下一把武器的起点上。

目前所有系统跑在 Godot 4 的 GDScript 项目里(`godot-prototype/`),纯本地运行,存档存在用户目录。

## 现在能玩到什么

- **锻造四步**:熔炼 → 锻打 → 热处理 → 装配,每一步的选择都会写进武器事实卡(材料特性、缺陷、尺寸、淬火介质),神只引用这些事实。
- **神前交涉**:可以选内置脚本神,也可以接云端 AI 神(OpenAI 兼容端点,实测 DeepSeek 官方可用)。开始界面填端点/密钥/模型名,保存时会立刻探测连接并预加载交涉上下文(系统提示、武器档案、判例库);交涉按钮按帧轮询,不卡界面。
- **武装间**:神裁之后,铁匠铺武器进入武器库,在武装间给小队三人的任一人装备/换装。新游戏自带三把演示武器(誓约盾锤、嗜血之刃、灼烧之弓),分别带一个演示契约。
- **六边形战斗**:确定性模拟(固定 20Hz、种子+输入决定一切),布阵拖动、主动技按钮、逐帧快照回放;伤害是六区乘区(基础攻击×动作倍率×增伤区×暴击档×防御区×独立区),DoT、控制、灼烧格、远程弹道都在里面。
- **日结算**:打完回铁匠铺自动结算(赏金/声望/天数+1/重伤与休整),材料库存支撑锻造消耗。

## 跑起来

```powershell
# 测试(163 项断言)
godot --headless --path godot-prototype -s res://tests/run_headless.gd

# 完整流程入口(锻造台)
godot --path godot-prototype scenes/forge/forge_scene.tscn
```

开发常用的命令可以走 `scripts/devkit.ps1 test|run|smoke|diag|quit`,它封装了全量测试、启动、冒烟、诊断脚本和关闭窗口,具体见 `docs/godot-devkit.md`。

## 目录

- `godot-prototype/` — 游戏本体。内部按 场景 → 应用用例 → 领域规则 → 数据资源 分层:
  - `app/` 应用根(GameApp 单例、RunState、路由、存档)
  - `domain/` 领域逻辑(战斗、武器、内容表、经济、谈判协议)
  - `application/` 用例(日结算、装备、神祇适配器工厂)
  - `adapters/` 外部接口(脚本神、本地/云端 AI、连接探测、上下文构建)
  - `scenes/` 锻造台、神裁砧、武装间、战斗四个场景
  - `core/` MechLang 机制语言、战斗模拟器、数值表(balance.gd 是唯一数值入口)
- `docs/` 调研与工具文档(自走棋源码研究、Godot 开发工具包)
- `scripts/` devkit.ps1 与文档工具
- `session-log.md` 开发日志

## 设计文档

根目录的 `game-plan.md`、`core-gameplay-design.md` 等是早期的企划稿,系统边界以代码为准;协议相关在 `godot-prototype/tests/negotiation/PROMPT_god.md`(AI 神的输出格式和裁决规则)。

## 说明

- API 密钥和游戏存档都在本机用户目录,不会进仓库;仓库里刻意排除了一切 `run/`、`saves/`、`build/` 目录和 `.dat` 文件。
- 云端 AI 神是可替代的实现:适配器接口在 `domain/negotiation/divine_adjudicator.gd`,换模型或接本地推理只要适配 `adjudicate(facts, app) -> DivineTurn` 即可。
- 认怂解释:如果 AI 神给的契约草案没通过 MechLang 校验,游戏会给它一次修正机会;还不行就以它的文字描述为准展示,不会卡死交涉流程。
