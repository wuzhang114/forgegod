# AI-Tetra 生成与神裁幻境设计

> 目的：说明如何让 AI 在玩家指引下创造 Tetra-compatible 效果，并在玩家确认前用可重复的动态演示验证和返修。

## 1. 设计立场

AI 的价值不是替玩家点选一个预制技能，而是把“材料事实 + 玩家幻想 + 神明反驳 + 代价选择”组织成新的机制结构。玩家可以提出“围绕勇者飞行的激光无人机”这类功能想法，但西幻世界中的实现应被翻译为有来源的火花小精灵、矿灵、投射物或法阵，并附带材料供能、耐久、冷却和可被敌人利用的反制。

开放的是机制组合和世界观解释，不开放服务器权限。AI 不能生成 Java、命令、函数、任意 NBT、任意资源路径或无界循环。

## 2. 数据流

```text
Tetra ItemStack
   -> WeaponFacts（服务端事实快照）
玩家自然语言申请 + 事实卡片
   -> 锻造之神多轮质询
   -> EffectBlueprint（AI 唯一输出格式）
   -> Schema / 事实 / 权限 / 强度 / 可终止性校验
   -> TetraCompiler
   -> 世界专用 generated datapack
      data/tetra/item_effects/forgegod/...
      data/tetra/improvements/shared/forgegod/...
   -> 受控 reload + 唯一 improvement 挂载
   -> 神裁幻境动态演示
   -> 接受、返修、选择历史版本或放弃
   -> 定稿 DivineContract + 正式武器
```

## 3. EffectBlueprint 约定

AI 返回的蓝图至少包含：

```json
{
  "blueprint_version": 1,
  "name": "银木火花之约",
  "fantasy": "连续命中后召来火花小精灵追击标记目标",
  "cited_fact_ids": ["material.silverwood.spirit_affinity"],
  "entrypoints": [{"event": "ON_HIT", "start_node": "counter"}],
  "nodes": [
    {"id": "counter", "op": "COUNTER_WINDOW", "args": {"count": 3, "window_ticks": 200}, "next": "sprites"},
    {"id": "sprites", "op": "SUMMON_FAMILIAR", "args": {"type": "SPARK_SPRITE", "count": 2, "lifetime_ticks": 160}, "next": "cost"},
    {"id": "cost", "op": "DAMAGE_WEAPON", "args": {"amount": 3}, "next": null}
  ],
  "limits": {"cooldown_ticks": 600, "max_spawned_entities": 2, "max_steps_per_trigger": 24}
}
```

节点只使用注册过的 `op`。首版安全集合包括条件、计数器、标记、伤害、状态、击退、粒子、声音、延迟、有限分支、有限重复、受控投射物、火花小精灵、短时区域、跟随/环绕/追踪、耐久/生命/供物消耗和冷却。

校验器必须拒绝：命令、函数、任意实体 NBT、任意方块读写、永久加载区块、负数或溢出数值、无限循环、没有终止条件的召唤和超过单次/每 tick/全局预算的图。

## 4. Tetra 编译与动态文件

编译器不是字符串模板拼接器，而是把规范化蓝图转换为已知的 AST，再序列化为 JSON。所有输出路径由 `contract_id` 生成，AI 不能影响 namespace 或文件名。

安全映射：

| 蓝图内容 | 编译目标 |
|---|---|
| 命中、右键、挖掘等 Tetra 触发器 | `data/tetra/item_effects/forgegod/` |
| 条件、伤害、状态、粒子、声音、有限延迟 | Tetra 原版 effect outcome |
| 小精灵、受控投射物、武器损耗、标记、区域和复杂状态 | 本 MOD 注册的 custom item effect |
| 共享模块改造 | `data/tetra/improvements/shared/forgegod/` 的唯一 improvement |
| `ON_HURT`、`ON_KILL`、时间窗口和跨事件状态 | Forge 事件适配 + 本 MOD runtime；不假装是原版 Tetra trigger |

流程采用临时目录 -> 全量解析 -> 哈希 manifest -> 原子替换 -> reload。失败时恢复上一 manifest。旧候选被放弃后先取消挂载，再延迟清理文件，确保没有物品仍引用正在删除的定义。

## 5. 神裁幻境

神裁幻境是候选效果的“可观察编译结果”，不是一段预录视频。它借用 Create Ponder 的镜头、暂停、逐步推进和重点标注，但使用真实服务端临时空间或独立维度；候选武器是正式武器的副本，正式材料、耐久和供物不受影响。

### 自动模式

- `ON_HIT`：测试人偶、自动攻击者和可重复攻击脚本。
- 连击：按蓝图要求连续命中同一目标，展示计数窗口如何归零。
- `ON_HURT`：可控敌人从固定伤害档攻击演示者。
- `ON_KILL`：生成低生命目标，展示击杀前置与后续效果。
- 右键：自动发动，显示冷却、资源消耗和失败条件。
- 区域：在 4、8、16 格等距离放置目标，验证半径、视线和阵营条件。

### 手动模式

玩家可以接管演示者移动和攻击，亲自测试“这个效果是否好用”。暂停/慢放只冻结幻境调度器，不暂停主世界；重播从同一场景快照和随机种子恢复。

### 反馈 trace

演示记录节点执行时间线、触发事件、目标、伤害/状态/击退、冷却、耐久、召唤物和区域的数量与寿命，以及“条件不满足、超出预算、目标无效、契约熔断”等原因。玩家可点击某一时间线节点提出反馈。

## 6. 有限返修闭环

### 6.1 双方案与 GUI 主流程

神明每次完成一次提案或返修，都必须返回两套结构化 `EffectBlueprint`，并分别附带简短的理由、触发方式和代价说明。方案一偏稳定、低代价；方案二允许更大胆的机制组合，但仍必须通过同一套事实、预算和执行安全校验。玩家在神裁砧 GUI 的两张方案卡片中选择其一，也可以在同一个输入框里写下自己的申请或返修意见，让下一轮 AI 继续给出两套方案。

正式玩家流程不依赖命令：右键神裁砧打开 GUI，放入武器和供物，输入申请，点击“请神”，查看两张提案卡，选择后进入神裁幻境。`/forgegod ask`、`/forgegod repair` 等命令仅作为开发测试和故障复现入口。GUI 打开时由服务端重新同步当前会话，避免上一次会话的方案残留。

默认每次神裁有 2 次玩家返修；高完成度或特定供物可增加 1 次，原型上限 4。第一次候选是 `candidate_v1`，每次有效返修递增版本号。

返修请求包含：

- 上一版蓝图和候选显示文本。
- 玩家从时间线选择的问题节点。
- “必须保留、希望修改、绝对不能接受”三类反馈。
- 实际演示 trace 和校验器警告。
- 当前剩余返修次数与不可改变的材料事实。

有效演示后玩家主动选择返修，才扣次数。API 失败、JSON 解析失败、编译失败、reload 失败、客户端断线、幻境清理失败和 MOD bug 不扣次数，并可重试或恢复上一有效候选。系统自动修复格式也不算玩家返修。

返修耗尽后：

1. 玩家可从所有成功演示的历史版本中任选一个定稿。
2. 可以放弃申请；未结算供物按规则退回，已明确消耗的仪式材料不回退。
3. 不得强迫玩家接受最后一次 AI 输出。

## 7. 代表性例子：火花小精灵

玩家申请：

> 连续射中同一个敌人三次后，叫出三只围着弓手飞的小精灵，帮他打被标记的敌人。

神明可能回答：

> 你的弓可以记住猎物，却没有维持三个灵体的火种。你愿意让它们每次出现都啃食一点弓弦耐久，还是把数量减为一只？

候选结果可以是：10 秒内连续命中同一目标 3 次，召来 2 只火花小精灵，环绕持有者 8 秒，优先攻击 16 格内的标记目标，触发时额外损耗 3 点耐久，冷却 30 秒；水中立即熄灭且小精灵可被攻击。

神裁幻境先展示第一版。玩家若反馈“保留环绕和标记，但小精灵经常打不到目标”，AI 可以把追踪半径改为 20 格、增加返回持有者的路径，或降低数量换取更稳定的锁定。若反馈“代价太重”，神明可以提出更长冷却、需要特定矿石供能或减少持续时间的反提案。每次修改必须在下一版演示中可观察。

## 8. 成功判据与数据集

不能用对白华丽或名字新奇判断 AI 创造力。每个候选至少记录：

- 玩家意图符合度与材料事实引用正确率。
- 机制图节点/边结构与历史候选的差异度。
- JSON/编译一次通过率和 reload 成功率。
- 演示可理解性、触发稳定性、实战可玩性。
- 返修前后改善幅度，以及玩家是否主动选择返修。
- 玩家“这是我创造的”评分、API 延迟和费用。

这些记录组成机制数据集，用于以后比较固定效果、AI 一次生成和多轮反馈生成，也为未来训练或评测本地模型保留可复现样本。

## 9. Ponder 借鉴边界

不直接把每个 AI 结果注册成 Ponder StoryBoard：StoryBoard 是预注册 Java 方法，新增场景需要重启，且 PonderWorld 与真实服务端战斗状态不同。首版只借鉴其表现语言：聚焦镜头、分步播放、重点标注、可暂停、可重播、明确因果。等神裁幻境证明玩法成立后，再考虑可选的 Ponder 入口用于展示已定稿的精选契约。
