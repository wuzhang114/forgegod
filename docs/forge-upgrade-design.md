# 锻造系统轻量升级方案 · 本源属性修正 + 部件名 + 适配 + 铭刻

> 原则:**主要玩法是神裁**。锻造不做重系统,只做三件轻事,
> 让"造了什么"能在神裁的时候说出来、并且真的有用。
> 其中「本源属性修正」已定稿(方案 A + 传导→魔法伤害增幅),见 §一。

---

## 一、本源属性修正(已定稿,先于部件化实施)

### 1.1 现状问题

材料现在有六维(hardness/toughness/density/conduction/stability/craft),
但真正参与公式的只有 3 个:硬度(热处理)、韧性(结构)、工艺(纯度)。
**密度、传导、稳定没有任何公式读取**;面板侧热处理"三吃"
(暴击+破甲+独立乘区),平衡"双吃"(命中+攻速)。后果:材料差异在
面板上体现太弱,玩家只能背词缀行文——与"主要玩法在神裁"冲突。

### 1.2 修正为五维(材料内部键不改,只改行文与公式)

| 本源 | 内部键 | 玩家向命名 | 职责 | 进哪条公式 |
|---|---|---|---|---|
| 锋刃 | hardness | 锋刃 | 杀伤面 | 破甲(材料直算)+ 热处理(作用件,不变) |
| 筋骨 | toughness + stability | 筋骨 | 耐久面 | 结构/耐久(不变)+ 命中小加成(新) |
| 重量 | density | 重量 | 手感面 | 平衡(操控件密度参与,新)+ 攻速(经平衡,不变) |
| 神性 | conduction | 神性 | **魔法面** | **魔法伤害增幅(新,核心改动)** |
| 净度 | craft + 熔炼 roll | 净度 | 伤害面 | 纯度→攻击(不变) |

### 1.3 面板重布(消除双吃/三吃)

| 面板项 | 现在 | 修正后 |
|---|---|---|
| atk_mult | 纯度 | **纯度(不变)** |
| crit_mult | 热处理 | **热处理(不变)** |
| shred 破甲 | 热处理(×0.02) | **材料锋刃**(硬度_avg,×0.03,clamp 0~0.15) |
| wbonus 独立区 | 热处理(×0.6) | **仅词缀给**(暂时恒 0,词缀接缝后续;注:契约 traits 仍可给) |
| hit | 平衡 | **平衡(主)+ 筋骨小加成**(α·韧_avg) |
| speed | 平衡 | **平衡(不变)** |
| durability | 结构 | **结构(不变)** |
| **magic_mult(新)** | 无 | **1 + (传导_avg − 5) × 0.06**,clamp 0.9~1.25 |

- 传导_avg = 作用件与介质件材料的传导均值(无介质件时取作用件);
- 硬度_avg / 韧_avg 分别取作用件 / 承力件材料值;
- 这些均值在 `forge_core.build` 的 craft 摘要里新增 3 个字段
  (conduction_avg / hardness_avg / toughness_avg),旧档与演示武器
  缺失时默认 5(不炸、不膨胀)。

### 1.4 魔法增幅的生效面(定死,不扩散)

只对**契约的机制伤害**生效,且仅限魔法系伤害类型:

- 物理/冲击/荆棘(physical / impact / thorns 等)→ **不增幅**;
- 魔法系(fire / lightning / radiant / void / electro / anemo / cryo /
  pyro / dark / tidal / beam / poison / withering …)→ 增幅
  (实现以 mechlang_def 的伤害类型表为准,归属清单写死在表上);
- 接缝点(规划定位):`sim_contract.gd` SimHost.action("damage")
  → `battle_sim.mechanic_damage(...)`,按 contract_id 取
  `contracts[contract_id].host.weapon.magic_mult`,乘入 amount;
  武器对象由战斗场景构造(`_battle_weapon()` 增加 magic_mult 字段,
  远征/演示两条路径同一来源);
- DoT(灼烧/中毒等状态跳伤)与弹道伤害走同一 mechanic_damage,
  顺带生效 —— **玩家对神裁出魔法机制的反应,和材料神性直接挂钩**;
- 数轴示例:熟铁(导 1)→ ×0.9;赤铜(导 8)→ ×1.18;虚空矿(导 8,介质
  件加持)→ ×1.25(封顶)。一把"赤铜+虚空矿"的武器,魔法契约伤害
  比"熟铁"高约 30%——这正是"材料影响神裁玩法"的落地。

### 1.5 平衡边界

- magic_mult 上不封底的替代方案(契约 budget 关联)已被否决——
  **不碰契约预算,只碰伤害**;
- 五维只改公式,不改存档结构(武器实例、facts、fingerprint 兼容;
  fingerprint 因 craft 增字段而变化,仅影响新锻造,旧武器已序列化);
- 测试面:test_weapon_stats 的 shred/wbonus/hit 断言更新;
  新增 magic_mult 断言(材料→增幅、非魔法类型不增幅)。

## 二、三件事(做完长这样)

1. **部件名随武器走**:锻战锤显示「锤头/锤柄/配重环/缚力符环」,长剑显示
   「剑身/剑脊/护手/柄首宝石座」,弓显示「弓臂/弓弦/握把/箭羽座」。
2. **材料 × 部件适配**:每材料标 1~2 个"最合手"部件和 1 个"勉强"部件。
   相合时部件词缀写成"★相合"(神裁论据 +1);勉强时多一条轻缺陷
   ("这料子不合这个位子");
3. **一次铭刻**(可选,替代复杂镶嵌):装配最后可嵌入 1 枚铭刻物,共 6 选 1:
   给一条词缀 + 一项面板微调(±3~5,只动一项)。消耗 1 晶石,装了就不能换。

数值公式、四段流程、淬火/技法、面板换算**全都不动**。
改动集中在:材料表加一行、武器表加部件名、装配段加一列按钮。

## 三、部件名(只换名,不换逻辑)

内部键仍 `action/bearing/control/medium`(存档结构不变),仅 UI 与词缀行文用专属名。

| 武器 | 作用件 | 承力件 | 操控件 | 介质件 |
|---|---|---|---|---|
| 战锤 | 锤头 | 锤柄 | 配重环 | 缚力符环 |
| 长剑 | 剑身 | 剑脊 | 护手 | 柄首宝石座 |
| 弓 | 弓臂 | 弓弦 | 握把 | 箭羽座 |

## 四、适配表(只标"合手"与"勉强")

材料加 `fit: {best: [部件角色], poor: 部件角色}`,缺省 = 普通。

| 材料 | 最合手(论据+1) | 勉强(轻缺陷) |
|---|---|---|
| 熟铁 | 承力件 | — |
| 赤铜 | 介质件 | 作用件 |
| 黑木 | 操控件 | 作用件 |
| 魔兽骨 | 承力件 | 介质件 |
| 陨铁 | 作用件 | 操控件 |
| 银木 | 操控件/介质件 | 作用件 |
| 虚空矿 | 介质件 | — |
| 霜钢 | 作用件 | 操控件 |

效果极轻:
- **相合**:部件词缀行文标注「★相合」;神裁时该词缀论据权重 +1(见 §四);
- **勉强**:该部件词缀变"打折"行文,并让四维里对应项 -3(只减一项,减在
  该材料四维的最高维上;不影响其它公式);
- **普通**:什么都不发生。

> 示例:陨铁锤头「★相合 陨铁【天外】:支持位移/星火类论证」,神裁时这话更重;
> 陨铁配重环则是「勉强 陨铁【天外】:又沉又不跟手(重心 -3)」。

## 五、铭刻(一次选择,不搞槽位)

装配段末加一行「可选:铭刻一枚」,6 选 1,装 1 枚即锁定:

| 铭刻物 | 词缀 | 面板微调 | 来源域 |
|---|---|---|---|
| 烈焰玛瑙 | 「火心」 | 淬火(热处理)+4 | 余烬山脉 |
| 寒霜晶 | 「寒息」 | 结构 +4 | 白棘冻原 |
| 雷击石 | 「引雷」 | 传导(淬火)+4 | 灰烬荒原 |
| 血珀 | 「嗜意」 | 平衡 +3 | 瘟疫洼地 |
| 星辉砂 | 「流辉」 | 平衡 +5 | 秽根密林 |
| 虚空晶 | 「窃隙」 | 淬火 +3 / 结构 -2 | 断界裂隙 |

规则:消耗 1 晶石(库存无 1 晶石则该选项目灰,提示可用金币 20 替代);
词缀只进 facts(神裁论据 +MechLang 无关,后续再评估查询)。

## 六、神裁接缝(本次锻造改动的全部意义)

系统已经用"武器事实"做神裁论据。新增两点:

1. **适配论据**:材料词缀按「★相合 / 打折 / 普通」给出权重(相合 ×1.5,打折 ×0.7),
   在 `prepare_context` 汇总论据时生效——这个"权重"目前只影响**交涉的
   引导文案**(神更认同你那套说法),不做硬性数值;
2. **铭刻词缀**作为一条新论据进上下文,让"镶嵌了虚空晶的剑"在神裁时
   可能引出虚空类机制的对话(与 RemoteAIAdapter 的现有 prompt 拼接)。

## 七、改动面

| 文件 | 改动 |
|---|---|
| `core/forge/forge_core.gd` | MATERIALS 加 `fit`;KINDS 加 `parts`(名称);新增 `SOCKETS` 表;facts 行文区分相合/勉强/普通;勉强 -3 只发生在该材料最高维 |
| `scenes/forge/forge_scene.gd` | 装配段显示部件名;材料卡上加「★合手/勉强」角标;装配段末加铭刻一行 |
| `domain/weapon/contract_explainer.gd` | 适配/铭刻词缀的读法(已有词缀显示,只加文本规则) |
| `adapters/negotiation/remote_ai_adapter.gd`(context) | 论据权重注记(相合/打折/铭刻)拼入 prepare_context |
| `tests/test_forge.gd` + 新用例 | 适配行文、勉强 -3 只减一项、铭刻指纹稳定 |

兼容:build 签名与 parts 键不变;旧存档武器 facts 已序列化,不受影响;
新材料(疫毒晶/血藤芯等,见世界设定文档)后续补 fit 与 SOCKETS 即可。

## 八、明确不做的(防复杂化)

- 不做部件属性加权公式(四维合成保持现状);
- 不做多槽/可替换/费用折损/词缀上限;
- 不做 MechLang `material()` 查询(以后想让契约读材料再说);
- 不做面板"总量守恒"条约;
- 不做每武器独立的一套适配表(三种武器共享同一张材料适配表,开头 9 行数据)。
